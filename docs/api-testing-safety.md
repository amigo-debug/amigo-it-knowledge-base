# 以安全方式測試付費雲端 API

測試會產生內容或用量的雲端 API 時，應先定義最小測試範圍。先以最短、非敏感的輸入驗證連線與授權；如服務提供不連線的預覽模式，應先確認請求結構，再進行一次實際請求。這種做法能同時降低成本、減少重覆執行，並讓錯誤更容易定位。

## 建議流程

| 階段 | 行動 | 原因 |
|---|---|---|
| 1. 範圍 | 定義單一功能、最短輸入、可接受的用量上限。 | 防止測試變成大量生成。 |
| 2. 憑證保護 | 從環境變數讀取憑證；不把憑證放進程式、文件、日誌或版本控制。 | 防止未授權使用與憑證外洩。 |
| 3. 乾跑 | 列印端點設定以外的請求結構與非敏感參數，不連線。 | 及早發現格式錯誤，且不產生用量。 |
| 4. 最小實測 | 只提交一次短請求，將輸出寫到隔離資料夾。 | 驗證實際授權和回應處理。 |
| 5. 錯誤分類 | 區分認證、權限、限流、輸入格式與服務端錯誤。 | 對症處理，避免盲目重試。 |
| 6. 記錄 | 記下時間、功能、最小輸入類型、結果與追蹤識別碼。 | 讓日後可以核對用量與支援查詢。 |

## 認證錯誤的處理原則

當服務回傳「憑證無效」或「未授權」時，應立即停止重試。先由帳戶擁有人確認憑證是否已撤銷、是否屬於正確的帳戶與方案，以及服務功能是否已授權。修正後，重新執行乾跑和一次最小實測即可。不要在對話、截圖或問題單中貼出完整憑證。

> 原則：乾跑驗證「請求寫得對不對」；最小實測驗證「帳戶和服務接不接受」。兩者都成功，才開始批量或正式工作。

## 常用術語

| 詞彙 | 解釋 |
|---|---|
| API | 讓程式以標準方式使用外部服務的介面。 |
| 環境變數 | 由電腦或部署平台安全地提供設定值的機制，不需要寫進程式碼。 |
| 乾跑 | 只展示或驗證將要執行的請求，不進行外部呼叫。 |
| 追蹤識別碼 | 服務端為一次請求提供的識別碼，可在排錯時引用。 |
| 最小可行測試 | 以最小輸入驗證一個關鍵功能是否可運作的測試。 |
