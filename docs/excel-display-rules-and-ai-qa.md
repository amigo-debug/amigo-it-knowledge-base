# Excel 顯示規則與 AI 自動化 QA

> 本文件只記錄可重用的技術方法，不包含任何院友姓名、床號、機構名稱、真實檔案內容或個人資料。

## 1. Excel 工作簿（Workbook）與工作表（Worksheet）

- **Workbook**：整份 Excel 檔案。
- **Worksheet / Sheet**：Workbook 入面的單一分頁。
- **Cell / 儲存格**：表格內的一格資料位置，例如 A1。
- **Row / Column**：橫行／直欄；資料處理時要分清「資料列」同「表頭列」。

院舍文件自動化時，唔可以只睇畫面。AI 要同時檢查：儲存格內容、欄位結構、樣式、隱藏設定、篩選範圍、列印設定及合併儲存格。

## 2. 內容差異（Value Diff）與格式差異（Style Diff）

- **內容差異**：同一位置的文字、數字、日期或公式不同。
- **格式差異**：內容相同，但字型、顏色、填色、邊框、對齊、換行、欄寬或列高不同。
- **差異報告（Diff Report）**：逐格記錄原本值、修正版值、差異類型及應採取的動作。

比較兩個版本時，第一步可用穩定鍵值（例如床號、記錄編號）對應資料列，唔好只用 Excel 行號。因為行號可能因新增或刪除資料而改變。

## 3. 穩定鍵（Stable Key）

**穩定鍵**係一個可以唯一識別同一筆資料的欄位。理想條件：

1. 每筆資料都有值。
2. 不可重複。
3. 資料排序改變時，鍵值仍然不變。
4. 比較前先檢查缺失及重複。

如果鍵值缺失或重複，AI 不應自行猜哪一列係正確，應輸出人工覆核清單。

## 4. 原始層（Raw Layer）與顯示層（Display Layer）

- **原始層**：保留來源檔案的原文及原始結構，作為追溯及恢復用途。
- **顯示層**：為特定工作場景整理的副本，例如廚房工作視圖。

將「沒有」轉成空白、將預設數量文字移除、將欄位隱藏，全部只應該發生在顯示層。唔可以因為畫面簡潔，就刪除原始資料。

> 隱藏（Hide）不等於刪除（Delete）：隱藏列／欄仍然存在，只係暫時唔顯示。

## 5. 資料標準化（Data Normalization）

資料標準化係將不同寫法整理成一致寫法，令員工容易閱讀及令程式容易判斷。例如：

- 移除只屬於顯示冗餘的預設「一份」字樣。
- 將「沒有」或「普通」等預設狀態在顯示層留白。
- 將長句按操作項目、餐次、星期或替代關係換行。
- 保留特殊餐、份量倍數、補充品及替代資料。

標準化前要先分辨：

- 係純粹文字簡化？
- 係資料分類？
- 係實際操作指示改變？

例如將一種通用餐具名稱換成一個具體餐具組合，屬於**語意／操作規則**，唔係普通格式轉換，必須有可啟用／停用的規則開關及 QA。

## 6. 可配置規則（Configurable Rules）

唔好將所有規則直接寫死在程式碼內。建議以規則登錄表（Rule Registry）管理：

| 欄位 | 作用 |
|---|---|
| Rule ID | 每條規則的唯一名稱 |
| 適用狀態 | 例如正常出餐、胃喉或其他狀態 |
| 來源欄位 | 規則讀取哪一欄 |
| 轉換前 | 原本文字／條件 |
| 轉換後 | 顯示層的文字／動作 |
| 是否語意改動 | 區分格式簡化與實際操作映射 |
| 啟用狀態 | 可以停用個別規則 |
| 覆核日期 | 記錄最近一次由主管確認的時間 |

咁樣改名、改標籤、停用規則或新增樓層狀態時，唔需要重寫整套程式。

## 7. 規則預覽（Rule Preview）

AI 真正改檔之前，應先列出：

- 總資料列數。
- 每種狀態的數量。
- 每個欄位預計會改幾多筆。
- 預計隱藏的列及欄。
- 新出現的狀態、重複鍵值、矛盾資料及不明數量。

只有規則清單清楚，先進入套用及輸出階段。這個步驟可以避免 AI 將一次性人工修改誤當成永久規則。

## 8. Excel 版面術語

- **Wrap Text / 自動換行**：同一格內把長文字分成多行，避免超出欄寬。
- **Row Height / 列高**：文字換行後要加高，否則內容會被遮住。
- **Column Width / 欄寬**：要按內容長度及工作場景調整；唔可以只靠預設寬度。
- **Freeze Panes / 凍結窗格**：捲動時保留表頭；長表格通常需要。
- **AutoFilter / 自動篩選**：讓使用者按欄位過濾資料；範圍應由表頭一直到最後一筆實際資料。
- **Merged Cells / 合併儲存格**：多格合成一格；程式寫入時通常只有左上角儲存格可以寫值。
- **Print Scale / 列印縮放**：控制列印時縮小比例；唔可以盲目複製固定百分比，要按實際欄位及文字長度 QA。

## 9. 自動 QA（Quality Assurance）

AI 輸出後至少檢查：

1. 原始檔案仍然存在並且沒有被覆寫。
2. 穩定鍵沒有缺失、重複或無故改變。
3. 只有符合條件的資料列套用標準化規則。
4. 非預設數量、特殊餐及替代要求沒有被刪除。
5. 隱藏列／欄仍然有資料。
6. 篩選範圍沒有包括尾端空白格式列。
7. 長文字沒有被截斷，沒有出現 `###`。
8. 每一項內容變更都有逐格差異紀錄。
9. 未知狀態及矛盾指示有列入人工覆核。

## 10. 院舍場景比喻

- 原始層好似院舍的正式紀錄簿：內容完整，方便追查。
- 顯示層好似廚房當日工作清單：只顯示今日真正需要快速閱讀的內容。
- 規則登錄表好似院舍的可更新 SOP：條件、例外及覆核日期清楚寫出，不靠某一位同事記憶。
- QA 好似交更前的雙人核對：唔係完成輸出就算，而係逐項證明冇漏資料、冇錯分類、冇誤刪內容。
